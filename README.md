# Profit Tracker — учёт заработков

Одностраничный трекер сделок: записываешь, за сколько купил и за сколько продал, приложение считает чистый заработок, маржу, ROI и показывает сводку за выбранный период.

Работает целиком в браузере: без бэкенда, без регистрации, без аналитики. Данные лежат в `localStorage`.

## Стек

- Vite + React 18 + TypeScript
- Tailwind CSS
- Собственный SVG-график, `lucide-react` для иконок
- Хранение: `localStorage` (ключ `profit-tracker.v1`)

## Локальный запуск

```bash
npm install
npm run dev
```

Сборка:

```bash
npm run build     # результат в dist/
npm run preview   # локальный просмотр собранной версии
```

## Структура

```
src/
  lib/profit.ts     # формулы прибыли, маржи, ROI, агрегаты — чистые функции
  lib/dates.ts      # периоды, локальные даты
  lib/format.ts     # форматирование денег и процентов (русская локаль)
  lib/storage.ts    # localStorage, миграции, экспорт/импорт
  lib/validation.ts # правила валидации формы
  hooks/            # useDeals, useToasts, useClock
  components/       # Header, PeriodTabs, KpiCards, ProfitChart, DealTable, модалки
  App.tsx           # сборка экрана
```

Вся бизнес-логика расчётов изолирована в `src/lib/profit.ts` и не обращается к DOM — её можно тестировать и переиспользовать.

## Данные и бэкап

- Всё хранится в браузере, на устройстве пользователя. Очистка кэша = потеря данных.
- Экспорт: кнопка в шапке → JSON (полный бэкап) или CSV (для Excel, с BOM и `;`).
- Импорт: JSON с режимами «Заменить всё» / «Добавить к текущим».
- Перед «Очистить всё» бэкап скачивается автоматически.

## Публикация

### Вариант 1 — GitHub Pages (бесплатно, без сторонних сервисов)

1. Создать на GitHub пустой репозиторий (без README и .gitignore).
2. Запушить код:

```bash
git remote add origin https://github.com/<username>/<repo>.git
git push -u origin main
```

3. В репозитории: **Settings → Pages → Source: GitHub Actions**.
4. Workflow `.github/workflows/deploy.yml` соберёт проект и опубликует его на
   `https://<username>.github.io/<repo>/` при каждом пуше в `main`.

Базовый путь (`base`) подставляется из имени репозитория автоматически, менять `vite.config.js` не нужно.

### Вариант 2 — Vercel или Netlify (свой домен, превью-деплои)

Импортировать репозиторий из GitHub, настройки определятся сами:

- Framework: Vite
- Build command: `npm run build`
- Output directory: `dist`

Оба сервиса дают публичный URL сразу после первого деплоя и позволяют привязать собственный домен.

## Важно про «сайт для всех»

Это статическое приложение: страница открывается у любого посетителя, но **данные у каждого свои** — они пишутся в его браузер, а не на сервер. Чтобы сделки были общими (например, для команды или просмотра чужих цифр), нужен бэкенд и авторизация — это отдельный этап, архитектура под него в коде заложена, но сейчас его нет.
